# Agent Dashboard — Command Center

## What this is
Single-page HTML dashboard showing all agents, projects, orchestrator state, live services, Mac Mini M4 status, Linear issues, CodexBar usage, and comms bus. Auto-generated by a Python pipeline.

## Source files

| Path | Role |
|---|---|
| `builder/` | Git-managed source of truth for dashboard builder |
| `builder/build-agent-dashboard.py` | Thin entry point — calls `dashboard_builder` package |
| `builder/dashboard_builder/` | Modular Python package (config, agents, projects, comms, linear, metrics, codexbar, orchestrator, live, html_builder, md_builder) |
| `builder/dashboard-assets/style.css` | Extracted CSS |
| `builder/dashboard-assets/script.js` | Extracted JS (sidebar nav, mode slider, local services probe) |
| `builder/deploy_to_scripts.sh` | Copies git-managed source into the Mac Mini runtime `~/scripts` and validates build |
| `~/scripts/` | Runtime copy used by launchd/rebuild scripts |

## Output

| File | Description |
|---|---|
| `~/agent-dashboard.html` | Full HTML dashboard (opened in browser) |
| `~/agent-dashboard/index.html` | Git-tracked copy for GitHub Pages |
| `~/ObsidianVault/90-Operations/second-brain/reports/YYYY-MM-DD -- agents-dashboard.md` | Obsidian markdown snapshot |

## Data sources

- **Projects**: scanned from `~/ObsidianVault/20-Projects/*/Tech-Base/TODO.md`
- **LUMUS**: parsed from `~/ObsidianVault/LUMUS-CONTEXT.md`
- **Comms**: `~/.agent-bridge/comms.jsonl`
- **Live feed**: `~/scripts/live-feed.json` (generated by `generate-live-feed.py`)
- **Health**: `~/.agent-bridge/health/*.json`
- **Orchestrator**: `~/.agent-bridge/orchestrator.json`
- **Usage**: `~/.agent-bridge/usage_snapshots.json`
- **Token ledger**: `~/.agent-bridge/token_ledger.jsonl`
- **CodexBar**: `~/Library/Group Containers/group.com.steipete.codexbar/widget-snapshot.json`
- **Linear**: via `~/.claude/lib/linear_api.py` CLI
- **Daily Work**: `~/.agent-bridge/daily-work/` written by `daily_work_collector.py` (launchd `com.pirajoke.daily-work-collector`, every 2 h). `sessions/<machine>/<day>.json` from Claude Code (`~/.claude/projects`) and Codex (`~/.codex/sessions`) logs; `github.json` from the GitHub API (Mac mini only, `--github`). Other Macs install it with `builder/install_daily_work_collector.sh --machine <name> --push-to maxxs-mac-mini`. Served by `/api/work/daily` (numbers only without the owner token) to the MAIN MANAGER tab (`?tab=work`). Day files (schema 2) also keep a few redacted asks and the agent's last reply per session, and `github.json` keeps a short PR description; these feed the summarizer only and are never served.
- **Day summaries**: `~/.agent-bridge/daily-work/summaries/<day>.json` written by `daily_work_summarizer.py` (launchd `com.pirajoke.daily-work-summarizer`, every 3 h, Mac mini only, installed with `--summaries`). For finished days of the last 14 whose activity changed, it calls the Claude Code CLI signed in on the Mac mini (`claude -p`, no API key, cwd `~/.agent-bridge/daily-work/summarizer`, which the collector skips) and stores 1–4 product-language bullets per project, at most 3 days per run. `summaries/status.json` records the last run and errors such as `claude_not_found` or `claude_auth_failed`. Because a launchd job can't always read the login keychain, the summarizer passes a long-lived token from `claude setup-token`, saved in `~/.agent-bridge/claude_oauth_token` (mode 600), to the CLI as `CLAUDE_CODE_OAUTH_TOKEN`, with any spaces or line breaks from a wrapped terminal paste removed. Error text is redacted (the saved token, its pieces, `sk-ant-…`, `Bearer …`) before it reaches `status.json` or the log. Every call runs with no tools and no MCP servers (`--tools "" --strict-mcp-config`) and `CLAUDE_CODE_SUBPROCESS_ENV_SCRUB=1`, so nothing the model reads can reach that token; a CLI too old for `--tools` is reported as `claude_too_old` instead of being run with tools. Owner-only: shown in «Обзор дня», on project cards and in each project's day feed. Product descriptions live in `PRODUCTS` in `dashboard_builder/daily_work.py`.
- **Infra change log**: `~/.agent-bridge/infra-changes/<machine>/` written by `infra_change_collector.py` (launchd `com.pirajoke.infra-change-collector`, every 10 min, installed together with the Daily Work collector). Each run snapshots launchd plists and jobs, Docker containers, Homebrew services, listening ports, git checkouts in `~`, `~/scripts`, `~/.cloudflared` and crontab, and appends the differences to `events-YYYY-MM.jsonl`. `/api/infra/changes` merges these with infra-changing shell commands that Claude Code and Codex ran (from the Daily Work session files) and merged PRs (from `github.json`); numbers only without the owner token. The MAIN MANAGER tab uses the Property OS visual language, scoped to `.mm-os`; the rest of Command Center keeps its own design.
- **JARVIS Pipeline**: `/Users/pirajoke/jarvis` git checkout, `launchctl` service state, `/tmp/jarvis-bot.err` AIOS startup log, and `/Users/pirajoke/jarvis/data/jarvis.db` `answer_sources`

## Pipeline

```
generate-live-feed.py  →  live-feed.json
                              ↓
build-agent-dashboard.py  →  agent-dashboard.html + agents-dashboard.md
                              ↓
dashboard-rebuild.sh      →  copy to ~/agent-dashboard/index.html + git push
```

The runtime scripts run from `~/scripts`. Source edits should be made in `builder/`, then applied with `builder/deploy_to_scripts.sh`.

## How to rebuild manually

```bash
cd ~/scripts && python3 build-agent-dashboard.py
```

To apply git-managed source to runtime first:

```bash
cd ~/agent-dashboard && builder/deploy_to_scripts.sh
```

## Module structure

```

├── projects.py        # Scan projects, count TODOs, parse LUMUS
├── comms.py           # Read comms bus, chat-style HTML
├── linear.py          # Fetch Linear issues, render HTML
├── metrics.py         # Load agent metrics, render leaderboard
├── codexbar.py        # CodexBar provider usage bars
├── orchestrator.py    # Mode slider, subscriptions, budgets
├── live.py            # Live feed, events, health, Mac Mini panel
├── jarvis_pipeline.py # JARVIS runtime/deploy/source-aware card
├── html_builder.py    # Full HTML assembly
└── md_builder.py      # Obsidian markdown output
```
